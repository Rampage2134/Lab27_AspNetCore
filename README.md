## Что такое ASP.NET Core?

**ASP.NET Core** — это современный, кроссплатформенный фреймворк от Microsoft
для создания веб-приложений и API. Он работает поверх платформы .NET и заменяет
устаревший ASP.NET Framework.

#### Основные особенности ASP.NET Core:

- Работает на Windows, macOS, Linux;
- Высокая производительность (входит в топ быстрейших веб-фреймворков);
- Встроенная поддержка DI (Dependency Injection);
- Единая платформа для Web API, MVC, Razor Pages;
- Легко разворачивается в Docker и облаке.

## Что изучили?

**Middleware** — это цепочка функций, через которую проходит каждый HTTP-запрос,
прежде чем дойдёт до обработчика. Это аналог цепочки фильтров.

Когда вы открываете сайт в браузере, происходит следующее:

1. Браузер отправляет HTTP-запрос на сервер (например, GET /about).
2. Сервер получает запрос и определяет, какой обработчик вызвать (маршрутизация).
3. Обработчик выполняет нужную логику и возвращает HTTP-ответ.
4. Браузер получает ответ и отображает его пользователю.

## Список реализуемых маршрутов

**1. Главная**

```CS
app.MapGet("/", () => Results.Ok(new
{
    Message = "Добро пожаловать!",
    Version = "1.0",
    Time = DateTime.Now.ToString("HH:mm:ss")
}));
```

**2. Информация о студенте:**

```CS
app.MapGet("/me", () => Results.Ok(new
{
    Name = "Иванов Иван",
    Group = "ИСП-234",
    Course = 3,
    Skills = new[] { "C#", "HTML", "CSS", "JS", "ASP.NET" }
}));
```

**3. Калькулятор:**

```CS
app.MapGet("/calc/{a}/{b}", (double a, double b) => Results.Ok(new
{
    A = a,
    B = b,
    Sum = a + b,
    Diff = a - b,
    Mul = a * b,
    Div = b != 0 ? a / b : 0
}));
```

**4. Маршрут не найден:**

```CS
app.MapFallback(() => Results.NotFound(new
{
    Error = "Маршрут не найден",
    Code = 404
}));
```

## Интересные факты

#### Ключевые аспекты использования в крупных проектах:

- **Гипермасштабируемость** и производительность: ASP.NET Core демонстрирует высокую эффективность в облачных вычислениях, часто превосходя конкурентов по количеству обрабатываемых запросов в секунду.
- **Архитектурные подходы:**

1. Микросервисы: Широко используется для создания независимых сервисов, которые легко масштабируются.
2. Инкрементальная миграция: Крупные компании (например, в сфере туризма) часто запускают старые приложения на .NET Framework и новые на ASP.NET Core параллельно.

- **Безопасность и надежность:** Встроенные механизмы аутентификации и авторизации делают его пригодным для систем, требующих высокого уровня защиты и долгосрочной поддержки (7+ лет).
- **Бизнес-преимущества:** Большое сообщество и количество специалистов на рынке облегчают найм и адаптацию команд, что снижает операционные риски.

#### Реальные примеры и сценарии

- Крупные корпорации: Платформы с миллионами посещений в день используют комбинацию версий .NET для обеспечения стабильности.
- Гибридные решения: Некоторые проекты сочетают мощь ASP.NET Core для бизнес-логики с другими технологиями для API-шлюзов.

## Вопросы:

**Чем Minimal API отличается от MVC в ASP.NET Core?**

- MVC (Model-View-Controller): Использует тяжеловесную архитектуру с контроллерами, наследуемыми от ControllerBase, маршрутизацией через атрибуты или соглашения и разделением на модели, представления и контроллеры. Идеально для крупных, сложных приложений.

- Minimal API: Позволяет определить маршрут и логику прямо в Program.cs в 1-3 строках кода. Нет необходимости создавать классы контроллеров. Подходит для микросервисов и небольших API.

**Что произойдёт, если поставить app.MapGet(...) до app.Use(...)?**

Если вы вызываете app.MapGet до app.Use, это сработает, потому что Minimal API эндпоинты в ASP.NET Core регистрируются как терминальные middleware.

**Почему ASP.NET Core преобразует PascalCase в camelCase при сериализации
JSON? Это исследовательский вопрос — поищите ответ в документации или
статьях**

ASP.NET Core использует System.Text.Json по умолчанию.

- Причина: В экосистеме JavaScript (и в большинстве API) стандарт именования свойств JSON — camelCase (например, userName вместо UserName).
- Чтобы соответствовать стандартам веб-разработки и упростить жизнь фронтенд-разработчикам, разработчики ASP.NET Core сделали camelCase поведением по умолчанию (через JsonNamingPolicy.CamelCase).

**Что означает код ответа HTTP 401? А 404? А 200?**

- 200 (OK): Запрос успешно обработан.
- 401 (Unauthorized): Пользователь не аутентифицирован. Требуется предоставить учетные данные.
- 404 (Not Found): Сервер не может найти запрошенный ресурс (маршрут не существует).

**Чем dotnet run отличается от dotnet watch run?**

- dotnet run: Компилирует и запускает проект один раз. Если вы измените код, нужно вручную остановить процесс (Ctrl+C) и запустить снова.
- dotnet watch run: Работает в режиме наблюдения. Как только вы сохраняете любой файл в проекте, dotnet watch автоматически обнаруживает изменения, пересобирает проект и перезапускает его. Это значительно ускоряет разработку.
